Quick refresher

class Name: defines a blueprint. __init__(self, ...) sets up each new object, and self is the object being built. Call the class to make an object: Cup(). Read and set attributes with dot notation. A method is a def inside the class that starts with self, and you call it without passing self. A value written under the class line is a class attribute, shared by every object. A parameter written size="small" has a default, used when you leave it out. class Child(Parent): builds on a parent class, and super().__init__(...) runs the parent's setup first.

class Cup:
    def __init__(self, size="small"):
        self.size = size

    def describe(self):
        return "a " + self.size + " cup"

c = Cup()
d = Cup("large")
print(c.describe())
print(d.describe())
a small cup
a large cup

A coffee window in Hialeah writes down every order: who ordered, the size, and the price. Then make a third order, set nothing, and print vars(order3) to see the starting values.

How to think about the plan

  1. The class comes first. __init__(self) sets up each new order, and self is the order being built.
  2. order1 = CoffeeOrder() makes the object. The parentheses matter: they call the class.
  3. Set the attributes one by one with dot notation: order1.name = "Ana".

Think first

  • What does self stand for inside __init__?
  • What will vars(order3) show if you never set anything on it?
  • If you change order1.size later, does order2.size change too?

At the same window, an order also has a number of cups. A cup costs 3 dollars. Build CoffeeOrder with __init__(self, name, price, cups), a method total() that returns the price times the cups, and a method add_cups(more) that adds to the cups. Ask Name: and Cups: , make the order, and print Ana: 2 cups, total $6 (with the typed values). Then add 3 more cups and print the same line again.

How to think about the plan

  1. Constructor parameters mean the order is filled in the moment it is made: CoffeeOrder(name, 3, cups).
  2. A method is a def inside the class. Its first parameter is always self, and you do not pass it yourself.
  3. total() should return a number so the caller can print it. add_cups() changes the object, so it needs no return.
  4. input() gives text. cups needs int() before it goes in the order.

Think first

  • Why does the call order.total() have empty parentheses when the def has (self)?
  • What does order.cups hold after add_cups(3)?
  • Which attribute does total() read, and which does add_cups() change?

class CoffeeOrder:
    def __init__(self, name, price, cups):
        self.name = name
        self.price = price
        self.cups = cups

    def total(self):
        return self.price * self.cups

    def add_cups(self, more):
        self.cups += more

name = input("Name: ")
cups = int(input("Cups: "))

order = CoffeeOrder(name, 3, cups)
print(f"{order.name}: {order.cups} cups, total ${order.total()}")

order.add_cups(3)
print(f"{order.name}: {order.cups} cups, total ${order.total()}")

A bakery in Little Havana makes pastries, and the owner wants to know how many have been made. Build a Pastry class. Two class attributes sit under the class line, before __init__: PER_BOX = 6 (a box holds 6, shared by every pastry) and made = 0 (a counter). Each pastry has its own name and price, and every new pastry adds 1 to Pastry.made. Make Guava (2 dollars), Cheese (2 dollars) and Coconut (3 dollars), and print Guava costs $2 for each. Then print Pastries made so far: and the count, and Pastries in a box: with the box size read through the class and through an object. Last, try the trap: set guava.made = 99 and print guava.made: with its value, then Pastry.made: with its value.

How to think about the plan

  1. A class attribute goes directly under the class line. An instance attribute goes inside __init__ with self..
  2. To change the shared counter, use the class name: Pastry.made += 1.
  3. You can read a class attribute through the class or through any object. Both show the same shared value.
  4. Setting guava.made = 99 does not change the shared counter. It gives guava its own separate attribute that hides the class one.

Think first

  • Which value belongs to each pastry, and which belongs to the whole class?
  • Why is the counter updated with Pastry.made and not self.made?
  • After guava.made = 99, which of the three pastries see 99?

The window starts delivering to nearby buildings. The plan gives you the CoffeeOrder class from before, with name, price, cups and a total() method. Build a Delivery class derived from it. Its __init__ takes name, price, cups, fee, hands the first three to the parent with super().__init__(...), and saves fee itself. A new method total_with_fee() returns the order total plus the fee. How to think about the plan

  1. The parent class is already written. Your task is only the new class: class Delivery(CoffeeOrder):.
  2. The parent knows how to set up name, price and cups. super().__init__(name, price, cups) runs that setup for you.
  3. Then add what is new: self.fee = fee.

Think first

  • Which attributes does a Delivery get from the parent, and which are its own?
  • Why call super().__init__ instead of copying the three self. lines?
  • Does Delivery need its own total() method?

class CoffeeOrder:
    def __init__(self, name, price, cups):
        self.name = name
        self.price = price
        self.cups = cups

    def total(self):
        return self.price * self.cups

class Delivery(CoffeeOrder):
    def __init__(self, name, price, cups, fee):
        super().__init__(name, price, cups)
        self.fee = fee

    def total_with_fee(self):
        return self.total() + self.fee

trip = Delivery("Marta", 3, 4, 2)
print(f"{trip.name}: {trip.cups} cups, total ${trip.total()}")
print(f"With delivery fee: ${trip.total_with_fee()}")
print(vars(trip))
