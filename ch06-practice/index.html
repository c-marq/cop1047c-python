A · Define, call, return, pass in

Ch 6 Part 1 · zyBooks 6.1, 6.2, 6.5 · Write a function once, call it as many times as you need, send values in, and get a value back.

Quick refresher

def makes a function: a header (def name(parameters):) and an indented body. Nothing in the body runs until you CALL it: name(arguments). return sends one value back to the line that called it. A function with no return gives back None. Define the function above the code that calls it.

def cafecito_cost(cups):        # header: name and parameter
    return cups * 1.50          # body: send a value back

total = cafecito_cost(3)        # call: 3 is the argument
print(total)

A Calle Ocho ventanita prints the cost of a cafecito order. The code below works, but it isn't in a function. Move the math and the order line into a function named cafecito_order(). Keep the 'Ventanita receipt:' heading in the main program, then call the function.

How to think about the plan

  1. This is about WHERE code lives, not what it does. The output should be exactly the same before and after.
  2. The function needs a header with def, a name in lowercase with underscores, empty parentheses (no inputs yet) and a colon.
  3. Everything that belongs to the function is indented one level under the header.
  4. The main program starts back at the left edge: print the heading, then call the function. Defining it doesn't run it. Calling it does.

Think first

  • Which lines go inside the function, and which stay in the main program?
  • What happens if you define the function but never call it?
  • Does the heading print before or after the order line? Where does the call go?

    cups = 3
    price = 1.50
    print(f"{cups} cafecitos = ${cups * price:.2f}")

print("Ventanita receipt:")

At Sedano's, a shopper buys two items. Write a function named get_price() that asks for a price as a float and returns it. In the main program, call it twice, store each result in its own variable, then print the total with 2 decimals.

How to think about the plan

  1. The task repeats the same step twice: ask for a price. Any time code repeats, a function can do it once and be called twice.
  2. The function's job is to ASK and hand back the number. It shouldn't print the total. That's the main program's job.
  3. return is how the number gets out of the function. Without it, the function hands back None.
  4. Each call gives back one number, so catch each one in its own variable: price1 = get_price().

Think first

  • What does the function need to do, and what should it give back?
  • How do you get the number from inside the function to the main program?
  • How many times do you call it, and where does each result go?

Watch out

Forget the return and both variables hold None. Then the addition fails with TypeError: unsupported operand type(s) for +: 'NoneType' and 'NoneType'.

A Miami weather app shows temperatures to visitors from abroad. Write a function named to_celsius() with one parameter, the temperature in °F. It returns the temperature in °C using (F - 32) * 5 / 9. In the main program, ask for a temperature in °F and print the result with 1 decimal.

How to think about the plan

  1. Now the function needs something FROM us: the °F temperature. That's a parameter, a name inside the parentheses in the header.
  2. When we call it, we pass a value in. That value is the argument. The names don't have to match: the argument can be temp_f, the parameter fahrenheit.
  3. The function returns the answer instead of printing it, so the main program decides how to show it.
  4. Plan the main program in order: ask, call, print.

Think first

  • What goes in the parentheses in the header? What goes in the parentheses in the call?
  • Why return the Celsius value instead of printing it inside the function?
  • What is 95°F in Celsius? Work it out before you run the code.

def to_celsius(fahrenheit):
    return (fahrenheit - 32) * 5 / 9

temp_f = float(input("Temperature in °F: "))
temp_c = to_celsius(temp_f)
print(f"{temp_f}°F is {temp_c:.1f}°C")

Watch out

Calling to_celsius() with nothing in the parentheses stops with TypeError: to_celsius() missing 1 required positional argument: 'fahrenheit'. The parentheses must match: one parameter, one argument.

Bring back the Chapter 4 hurricane ladder, but inside a function. Write category(wind) that returns a message for a wind speed in mph: below 74 is 'Not a hurricane', 74 to 95 'Category 1', 96 to 110 'Category 2', 111 to 129 'Category 3', 130 to 156 'Category 4', 157 and up 'Category 5'. Call it for the three wind speeds in the plan and print each result.

How to think about the plan

  1. The if/elif ladder is the same as Chapter 4. The difference is that each branch RETURNS its message instead of printing it.
  2. return ends the function right away, so as soon as one branch returns, the rest of the ladder is skipped. Check the biggest speeds first.
  3. The main program calls the function once per speed. A for loop over the list does that without repeating the call three times.
  4. This is why functions matter: the ladder is written once and used as many times as we need.

Think first

  • What changes when a branch says return instead of print?
  • How does the main program call the function for each speed in the list?
  • Why can the next elif be simpler once the one above it has returned?

Show solution (try first)
speeds = [120, 70, 160]

def category(wind):
    if wind >= 157:
        return "Category 5"
    elif wind >= 130:
        return "Category 4"
    elif wind >= 111:
        return "Category 3"
    elif wind >= 96:
        return "Category 2"
    elif wind >= 74:
        return "Category 1"
    else:
        return "Not a hurricane"

for speed in speeds:
    print(f"{speed} mph: {category(speed)}")

Watch out

If the branches print instead of return, each line shows the category AND then None, because print(category(speed)) prints what the function returned, and a function with no return returns None.
