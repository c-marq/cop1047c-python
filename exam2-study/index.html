A · Validate, then count down

Like the exam lab Numbers Before · A while loop that rejects bad input, then a for loop with range() that counts backwards.

Quick refresher

Validation is START, TEST, CHANGE: ask once before the while, loop while the value is bad, ask again inside. Counting down uses a negative step, and the stop is never included, so stopping at 0 means the last number printed is 1.

num = int(input("Enter a number:\n"))
while num <= 0:
    num = int(input("\nInvalid. Enter a number:\n"))
for i in range(num - 1, 0, -1):   # num-1 down to 1
    print(i, end=" ")

A Brickell condo's elevator screen lists every floor below the one you're on. Ask for your floor number. If it's not a positive number (larger than 0), print an error and keep asking. Then print every floor below yours, from highest to lowest, separated by single spaces and always ending with 1. Each prompt ends with a new line, so the typing goes on the line below it, exactly like the exam lab.

How to think about the plan

  1. The output has two jobs that happen one after the other: first get a GOOD number, then count with it. Two loops in sequence, not nested.
  2. Getting a good number: we don't know how many tries it will take, so that's a while loop (validation: start, test, change).
  3. Counting: once we have the number, we know exactly how many floors to print, so that's a for loop with range().
  4. The range walks backwards: start one below the floor, step -1, and stop at 0 because the stop is never included. That makes the last number 1.
  5. Match the sample's blank lines: \n at the start of the error prompt and the summary heading, and \n at the end of each prompt.

Think first

  • What's the first number printed if you're on floor 8? The last?
  • Do you know how many times the user will type a bad number? So: while or for for the validation?
  • What range() gives 7 6 5 4 3 2 1 when the number is 8?
  • Where does the blank line before 'Invalid floor.' come from?

Watching a launch from Cocoa Beach? Ask for the number of seconds to count down, from 1 to 10. If the number is outside 1 to 10, print an error and keep asking. Then count down from that number to 1 on one line, separated by spaces, and print Liftoff! on the next line.

How to think about the plan

B · Build a list until the user is done

Like the exam lab Wine Request Form · Keep asking, reject blank entries, append to a list, and print the list at the end.

Quick refresher

Start with an empty list before the loop. Each pass: get a valid entry (a while loop that rejects ""), append it, then ask whether to continue. print(the_list) shows the list with brackets and quotes.

items = []
again = "Y"
while again == "Y":
    item = input("Item:\n")
    while item == "":
        item = input("Invalid. Item:\n")
    items.append(item)
    again = input("Another? (Y or N):\n")
print(items)

A Miami-Dade library branch takes requests for books it doesn't carry. Ask for the title and author of a book. If the user types nothing (an empty entry), print an error and keep asking. Store each request in a list. After each request, ask whether they want to request another book (Y or N). When they answer N, print the whole list.

How to think about the plan

  1. Two loops, one inside the other. The OUTER loop repeats while the answer is Y. The INNER loop repeats while the entry is empty.
  2. The list has to exist before the outer loop, or it starts over on every pass. Same rule as a counter: set up before, update inside, report after.
  3. The outer loop needs a starting answer of Y so it runs the first time. That's the 'play again' pattern from Part 2.
  4. Order inside the outer loop: ask for the book, validate it, append it, then ask Y or N. The append comes after validation, so a blank never gets in.
  5. print(requests) prints the list with brackets and quotes, which is exactly what the sample shows.

Think first

  • What has to exist before any loop starts?
  • Which loop is the validation, and which loop is 'keep going'? Which one goes inside the other?
  • If you put .append() before the empty check, what ends up in the list?

A DJ at a Kendall quinceañera collects song requests. Keep asking for a song until the user types DONE. A blank entry gets an error message. A song that's already on the list gets 'Already on the list.' and isn't added again. At the end, print how many songs were requested and a numbered list of them.

How to think about the plan

  1. This time there's no Y or N question. The user types a stop word, DONE, so it's a sentinel loop from Part 1: ask before the loop, test it in the while, ask again as the last line inside.
  2. Each entry is one of three cases: blank, already in the list, or new. That's one if/elif/else, and only the else appends.
  3. in checks whether the song is already in the list, same as checking a username in Ch 4.
  4. The numbered list at the end is enumerate() with i + 1, from Part 3. len() gives the count.

Think first

  • What's the sentinel, and where does it go: in a constant, the prompt, or the while condition?
  • Three possible cases for each entry. Which ones add to the list?
  • What gives you both the number and the song in the final loop?

C · Summarize given data

Like the exam lab Player Ranking Summary · Loop over a dictionary, sort each value into a group with if/elif, count each group, and flag the bad entries.

Quick refresher

The data is given. A for loop with .items() visits every name and value. An if/elif ladder puts each value in exactly one group, and in with a list checks several spellings at once. The last two branches catch the empty string (missing) and everything else (invalid).

for name, value in data.items():
    if value in ["Gold-1", "Gold-2"]:
        gold += 1
    elif value == "":
        print(f"{name} is missing!")
    else:
        print(f"{name} is invalid.")

The domino league at Máximo Gómez Park in Little Havana tracks each player's level in the dictionary in the plan. Expert-1 and Expert-2 both count as Expert. Same for Club and Rookie. A level that is empty is missing. Anything else is a typo. Print a message for each missing or invalid level as you find it, then print a summary with the count for each group and the number of errors.

How to think about the plan

  1. The data is already given, so there's no input. We have a collection, so it's a for loop, and with a dictionary we want the name AND the level: .items().
  2. Four counters: expert, club, rookie, errors. All start at 0 before the loop.
  3. Each level lands in exactly one place, so it's one if/elif/else ladder. in with a list checks both spellings of a level at once.
  4. Missing and invalid both count as errors but print different messages, so they're two separate branches: check for "" first, then else catches everything left.
  5. Error messages print inside the loop as we find them. The summary prints once, after the loop.

Think first

  • How many counters do you need, and where do they start?
  • Why does the empty-string check have to come before the final else?
  • Where do the error messages print, and where does the summary print?
