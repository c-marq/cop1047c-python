E · try and except, several handlers, raise, exceptions in functions

Ch 8 · zyBooks Chapter 8 · Catch the errors you expect, give each one its own message, and raise your own when a rule is broken.

Quick refresher

try holds the line that might fail; except runs only if it does. Name the error you expect: except ValueError, not a bare except, which also hides typos. One try can have several excepts, and the first match wins. raise ValueError("message") stops the program on purpose; except ValueError as err catches it, and print(err) shows the message. When a function raises, it ends right there, and the code that called it does the catching.

try:
    n = int("ten")
except ValueError as err:
    print("Caught:", err)
Caught: invalid literal for int() with base 10: 'ten'

A beach chair stand on South Beach rents chairs for $10 each. Ask How many beach chairs? until the customer types a whole number. For a word, a decimal or a blank, print Whole numbers only, like 3. and ask again. For a good number, print it like 3 chairs cost $30 and stop asking.

How to think about the plan

  1. int() fails with a ValueError on a word, a decimal or a blank. That's the one error to catch.
  2. A flag keeps the loop going: chairs_ok starts False, and the loop runs while not chairs_ok.
  3. Put the int() line and the print inside try. The last line of the try sets the flag to True.
  4. Name the error: except ValueError, not a bare except.

Think first

  • Which line can fail, and what's the name of the error it raises?
  • Where does the flag change, and why at the end of the try?
  • What should happen when someone types 2.5?

chairs_ok = False
while not chairs_ok:
    try:
        chairs = int(input("How many beach chairs? "))
        print(f"{chairs} chairs cost ${chairs * 10}")
        chairs_ok = True
    except ValueError:

Watch out

With a bare except: and a typo on the print line (chair for chairs), every good answer prints Whole numbers only, like 3. and the loop never ends. With except ValueError: the same typo stops right away with NameError: name 'chair' is not defined, so you can see the real bug. (That's the line Colab shows. Friends are splitting a $60 dinner check at a Cuban restaurant in Westchester. Ask how many people are splitting it and print each person's share with 2 decimals. A word gets Type a whole number of people. Zero people gets Someone has to pay! Enter at least 1.

How to think about the plan

  1. Two things can go wrong: the typing isn't a whole number (ValueError), or it's 0 and we divide by zero (ZeroDivisionError).
  2. Both risky lines go inside one try: the int() line and the division.
  3. Add one except for each problem, each with its own message.
  4. Show money with 2 decimals: :.2f in the f-string.

Think first

  • Which line raises the ValueError, and which raises the ZeroDivisionError?
  • Does the order of the two excepts matter here?
  • What happens with -2? Is that an exception?

A delivery app in Miami needs a 5-digit ZIP code. Write get_zip(): it asks Enter a 5-digit ZIP code: , strips the spaces, raises A ZIP code has exactly 5 digits. if it isn't 5 characters, raises Digits only, please. if it has anything but digits, and otherwise returns it. Below it, keep asking until a good one arrives, then print Delivering to and the ZIP code.

How to think about the plan

  1. The function's only job is to ask and check. It doesn't print the error: it raises it.
  2. raise ValueError("message") ends the function right there. The return line only runs when every check passed.
  3. The loop below calls the function inside try, and except ValueError as err prints the message.
  4. strip() first, so spaces around the ZIP code don't count. isdigit() from Chapter 7 checks that it's all digits.

Think first

  • What's the difference between raising the message and printing it?
  • Why does the try go around the function call, not inside the function?
  • Which check should come first, the length or the digits? Does it matter?

Show solution (try first)
def get_zip():
    zip_code = input("Enter a 5-digit ZIP code: ").strip()
    if len(zip_code) != 5:
        raise ValueError("A ZIP code has exactly 5 digits.")
    if not zip_code.isdigit():
        raise ValueError("Digits only, please.")
    return zip_code

asking = True
while asking:
    try:
        z = get_zip()
        print("Delivering to", z)
        asking = False
    except ValueError as err:
        print(err)

Watch out

Forget the return zip_code line and nothing crashes: a good ZIP code prints Delivering to None. A function with no return gives back None.

A ventanita keeps its prices in a dictionary with uppercase names: CROQUETA $1, PASTELITO $2, CAFECITO $2. Ask What would you like? , clean the answer so it matches the keys, and print it like PASTELITO costs $2. If the item isn't on the menu, catch the KeyError and print Sorry, we do not sell and the item.

How to think about the plan

  1. Looking up a key that isn't in a dictionary raises a KeyError.
  2. The keys are uppercase, so clean the answer first: strip() the spaces, then upper().
  3. Put the lookup inside try. One except: except KeyError.
  4. The f-string can look up the price right inside the braces: {prices[item]}.

Think first

  • What does prices["EMPANADA"] do when EMPANADA isn't a key?
  • Why clean the answer before the lookup?
  • Which line needs to be inside the try?
