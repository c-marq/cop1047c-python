D · Slicing, tables, string methods, split and join

Ch 7 · zyBooks 7.1, 7.2, 7.3, 7.4 · Cut pieces out of a string, line up columns, find and fix text, and turn a line of text into a list and back.

Quick refresher

A slice [start:end] starts at start and stops BEFORE end; a negative number counts from the right. In an f-string, {value:10} reserves 10 spaces; < is left, > is right, ^ is center, and the arrow goes before the width. count, find and replace search a string (find gives -1 when it's not there). Strings never change: methods return a NEW string, so save it. split() turns a string into a list of pieces; ", ".join(list) turns a list back into one string.

word = "Hialeah"
print(word[0:3], word[-3:])               # slicing
print(f"[{word:10}]", f"[{word:>10}]")    # width and alignment
print(word.count("a"), word.find("l"))    # count and find
print(" y ".strip().upper() == "Y")       # clean, then compare
print(" + ".join("a b c".split()))        # split, then join

A departures screen at Miami International shows each flight as one string, like AA1234 MIA to JFK. Use slicing to pull out four pieces: the airline (the first 2 characters), the flight number (the next 4), where it leaves from (the 3 letters after the space), and where it's going (the last 3). Print each piece with a label.

How to think about the plan

  1. Write the indexes under the string first. The first A is 0, and the space after 1234 is 6.
  2. A slice [start:end] starts AT start and stops BEFORE end. So the first 2 characters are [0:2].
  3. The origin starts right after the space, at 7. It's 3 letters long, so it stops before 10.
  4. A negative start counts from the right: [-3:] is the last 3 characters, whatever the length.

Think first

  • What index is the space after 1234? What index is the M in MIA?
  • Why is the end number always one more than the last index you want?
  • Why is [-3:] safer than [14:17] for the destination?

Watch out

Off by one is the classic slip: flight[7:9] gives only MI, because 9 is where it stops. A single index past the end, like flight[17], stops with IndexError: string index out of range. A slice past the end is fine.

A Little Havana bakery wants its price board printed as a neat table. Make two columns: ITEM, 20 characters wide and left aligned, and PRICE ($), 10 characters wide and right aligned. Put a line of 30 dashes under the header. The items are Cafecito 1.50, Pastelito 1.25, Croqueta 1.00 and Cafe con leche 3.75. Show every price with 2 decimals.

How to think about the plan

  1. Each row is one print with two f-string fields: the name, then the price.
  2. The width is the column. Use the same widths on every row so the columns line up.
  3. The alignment character goes BEFORE the width: :<20 and :>10.
  4. For a number, add .2f after the width to show 2 decimals: :>10.2f

Think first

  • Why do the header and every row need the same widths?
  • Where does the > go: before or after the 10?
  • What happens to a name that's longer than 20 characters?

A Miami Beach hotel's front-desk app fixes a common typo in guest messages: "teh" instead of "the". Ask for the guest's message. Print how many times "teh" appears, the index where the first one starts (find gives -1 if there isn't one), and the fixed message with every "teh" replaced by "the".

How to think about the plan

  1. count, find and replace all take the text you're looking for, in quotes.
  2. find gives the index where the first match STARTS, counting from 0, or -1 if it isn't there.
  3. replace doesn't change the message. It gives back a new string, so save it in a variable.
  4. All three are case sensitive: "Teh" with a capital T is a different string.

Think first

  • What does find give back when the typo isn't there?
  • Why do we need a new variable for the fixed message?
  • Will "Teh" at the start of a sentence be caught?

If you write message.replace("teh", "the") without saving it, the line runs and the new string is thrown away. Printing message then shows Fixed: Is teh pool open and teh bar too?. Strings never change: save the new one.

You're planning a Sunday cookout in Kendall. Ask for the guest names with spaces between them. Split them into a list, print how many guests there are, then print the names joined with a comma and a space. Finally ask "Save this list? (y/n): " and print "Guest list saved." if the answer is y or Y (even with extra spaces), otherwise "Guest list not saved."

How to think about the plan

  1. split() with NO argument splits on any number of spaces and ignores the ones at the ends. That's what you want when people type.
  2. split gives a list. len(list) tells you how many pieces.
  3. ", ".join(list) glues the pieces back into one string. The separator goes in front of .join.
  4. Clean the answer before you compare: answer.strip().upper() == "Y".

Think first

  • What's the difference between split() and split(" ") when someone types two spaces?
  • Is the result of split a string or a list?
  • After upper(), should you compare to "y" or "Y"?
