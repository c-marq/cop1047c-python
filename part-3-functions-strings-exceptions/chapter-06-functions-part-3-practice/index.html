C · Scope, two return values, recursion, docstrings

Ch 6 Part 3 · zyBooks 6.9, 6.10, 6.11, 6.12 · Pass values in and return values out, return two values as a tuple, read a recursive function, and document a function with a docstring.

Quick refresher

Variables created inside a function are local: they disappear when it ends. A global constant in ALL_CAPS (like SALES_TAX) can be read by any function, but everything else should be passed in. return a, b sends back one tuple; unpack it with x, y = f(). A recursive function calls itself and needs a base case to stop. A docstring is a triple-quoted string on the first line of the body, and help(name) shows it.

TAX = 0.07                       # global constant

def with_tax(price):
    """Return the price plus 7% tax."""
    return price * TAX + price   # price is local

def low_high(a, b):
    return a, b                  # two values, one tuple

low, high = low_high(3, 9)       # unpack
print(with_tax(100), low, high)

A Hialeah hardware store charges Miami-Dade's 7% sales tax. Create a global constant SALES_TAX = 0.07. Write register_total(price, qty) that returns price times qty plus the tax on it. In the main program, ask for the price (float) and the quantity (int), pass them in, and print the total with 2 decimals, like: Total with tax: $53.50

How to think about the plan

  1. The tax rate never changes, so it's a constant: a global in ALL_CAPS at the top.
  2. Everything else gets passed in. The function shouldn't use input() or read price from outside.
  3. subtotal is a local variable inside the function. The main program never sees it; it only sees what's returned.
  4. Format the returned value with :.2f inside an f-string.

Think first

  • Which value is a constant, and which values change every time?
  • What does the function need to receive, and what does it give back?
  • Can the main program print subtotal? Why not?

Miami's rainy season dumps a lot of water. Write rain_stats(inches) that uses a for loop to add up a list of monthly rainfall amounts and returns TWO values: the total and the monthly average. In the main program, unpack them into two variables and print both with 1 decimal.

How to think about the plan

  1. Same shape as calc_total_avg from class: total starts at 0, a loop adds, the average is computed AFTER the loop.
  2. return total, avg sends back one tuple with two values inside.
  3. In the main program, put two variables in front of the = to unpack them, in the same order as the return.
  4. Copy the given list exactly so your numbers match the target.

Think first

  • How many values come back, and in what order?
  • Where does the average get calculated: inside or after the loop?
  • What would happen with three variables in front of the =?

def rain_stats(inches):
    total = 0
    for month in inches:
        total += month
    avg = total / len(inches)
    return total, avg

rain = [9.5, 6.5, 8.5, 7.5]
season_total, season_avg = rain_stats(rain)
print(f"Total: {season_total:.1f} inches")
print(f"Average: {season_avg:.1f} inches")

Watch out

With one variable (stats = rain_stats(rain)), stats holds the whole tuple, and formatting it with :.1f stops with TypeError: unsupported format string passed to tuple.__format__. With three variables you get ValueError: not enough values to unpack (expected 3, got 2).

Here is a recursive function that counts down to launch. First, read it and predict its output on paper. Then run it as given. Finally, write count_down_loop(n), a version with a for loop and NO recursion, that prints exactly the same lines. Call it with 3 after the recursive call.

How to think about the plan

  1. Read the base case first: when n is 0, it prints Liftoff! and stops.
  2. Otherwise it prints n, then calls itself with n - 1. So 3 prints 3, then the call with 2 prints 2, and so on.
  3. A loop can count down too: range(n, 0, -1) gives n down to 1.
  4. After the loop ends, print Liftoff! once.

Think first

  • What is the base case, and what does it do?
  • What does each call do before calling itself?
  • Which range() counts from 3 down to 1?

def count_down(n):
    if n == 0:
        print("Liftoff!")
    else:
        print(n)
        count_down(n - 1)

count_down(3)

def count_down_loop(n):
    for i in range(n, 0, -1):
        print(i)
    print("Liftoff!")

count_down_loop(3)

Watch out

Without the base case (if n == 0), count_down never stops: it prints hundreds of numbers, then RecursionError: maximum recursion depth exceeded. A negative start like count_down(-1) does the same, because n never reaches 0.

A Coral Gables restaurant app asks for a tip percentage and only accepts 0 to 30. Write is_bad_tip(pct) with a one-line docstring. It returns True if the percentage is below 0 or above 30. Show the docstring with help(is_bad_tip). Then ask for the tip as an int, and keep asking while it's bad. Finally print the accepted tip.

How to think about the plan

  1. The docstring is the FIRST line of the body, in triple quotes. help(is_bad_tip) shows it, with no parentheses after the name.
  2. The function answers "is this wrong?", so it returns True on an error, just like validate_input in class.
  3. We don't know how many tries it will take, so it's a while: while is_bad_tip(tip): ask again.
  4. Store the new answer back in the same variable, or the loop never ends.

Think first

  • What does the function return for 40? For 18?
  • Why a while and not an if?
  • What happens if you forget to ask again inside the loop?
